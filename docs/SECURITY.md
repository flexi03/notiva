# Sicherheit

Notiva verarbeitet Dateien, die aus anderen Quellen stammen können (Sync, Downloads, geteilte Ordner).
Deshalb gilt **jede Datei als nicht vertrauenswürdig**.

| Risiko                     | Schutz                                                                                                                                                                                                              | Tests                                                                               |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| XSS über Markdown/HTML     | markdown-it + DOMPurify, verbotene Tags/Attribute, nur http(s)/mailto-Links, `rel="noopener noreferrer"`                                                                                                            | `markdown.test.ts`, `e2e/security.spec.ts`                                          |
| Code-Ausführung in Formeln | eigener Parser/Interpreter, kein `eval`/`Function` (ESLint), keine geerbten Schlüssel (`constructor`), Längen-/Tiefen-/Schrittlimits                                                                                | `formula.test.ts`                                                                   |
| YAML-Angriffe              | `core`-Schema (keine Tags), Alias-Limit (Billion Laughs), kein Prototype Pollution                                                                                                                                  | `frontmatter.test.ts`                                                               |
| Pfad-Traversal             | `assertSafePath` in jedem Adapter, im Electron-Hauptprozess zusätzlich `realpath`-Prüfung gegen Symlinks                                                                                                            | `path.test.ts`, `vault.test.ts`, `electron/vaultFs.test.ts`, `e2e/electron.spec.ts` |
| Manipulierte Adressen      | Routen werden validiert, unsichere Pfade führen zur Startseite                                                                                                                                                      | `settings-route.test.ts`, `e2e/security.spec.ts`                                    |
| Datenabfluss               | CSP: keine fremden Skripte, keine Frames/Objekte; Verbindungen nur zu `localhost` (lokale KI) und den bekannten KI-APIs; in Electron gar keine (KI läuft über den Hauptprozess); eigenes CSS ohne `url()`/`@import` | `e2e/security.spec.ts`, `e2e/electron.spec.ts`                                      |
| Electron                   | contextIsolation, Sandbox, kein Node, `app://` mit CSP, IPC nur vom eigenen Fenster, Navigation und neue Fenster gesperrt, Berechtigungen abgelehnt, DevTools nur unverpackt                                        | `e2e/electron.spec.ts`                                                              |
| Datenverlust               | atomares Schreiben (Desktop), Papierkorb mit Wiederherstellen, serialisierte Schreibvorgänge, Speichern beim Verlassen                                                                                              | `workspace.test.ts`                                                                 |

## KI (Assistent und MCP)

| Risiko                                    | Schutz                                                                                                                                                                                                                                                                                                                                       | Tests                                                                      |
| ----------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------- |
| Modell sendet unsinnige/bösartige Aufrufe | Jedes Werkzeug validiert seine Eingaben (Schema), Pfade nur über den Workspace (Pfad-Wächter), `database`-Schema und Prototypen nicht änderbar                                                                                                                                                                                               | `ai-tools.test.ts`, `mcp/server.test.ts`                                   |
| Prompt-Injection aus Notizen              | Systemprompt: Seiteninhalte sind Daten; zerstörende Werkzeuge (`trash_page`, `replace_page_body`, `remove_widget`) brauchen eine Bestätigung; Kacheln (`update_widget`) und Datenbanken (`update_database`, nur hinzufügen) werden vor dem Speichern geprüft; Nur-Lesen-Modus                                                                | `ai-agent.test.ts`, `e2e/assistant.spec.ts`                                |
| Datenabfluss über KI-Antworten            | Antworten werden als _untrusted_ gerendert: keine Bilder/Medien aus dem Netz, keine `style`-Attribute (Markdown-Bild-Exfiltration)                                                                                                                                                                                                           | `markdown.test.ts`, `e2e/assistant.spec.ts`                                |
| API-Schlüssel                             | nur auf dem Gerät (`localStorage`), nie im Vault (der synchronisiert wird); Anthropic-Header für Browserzugriff nur mit eigenem Schlüssel                                                                                                                                                                                                    | –                                                                          |
| Electron-Netzbrücke                       | `ai:request` nur vom eigenen Fenster, nur http(s), keine Zugangsdaten in URLs, Header ohne Zeilenumbrüche, Größenlimits, Zeitlimit                                                                                                                                                                                                           | `electron/aiRequest.test.ts`, `e2e/electron.spec.ts`                       |
| KI-Programme (CLI)                        | Nur bekannte Programme (claude, codex, agy – Antigravity im Planungsmodus mit `--sandbox`), Argumente baut der Hauptprozess; Claude Code: `--tools ""` (keine Shell/Dateien), `--strict-mcp-config`, nur Notiva-Werkzeuge vorab erlaubt, zerstörende nie; Eingaben (Modell, Sitzung) per Regex geprüft                                                                                   | `electron/aiCli.test.ts`, `e2e/electron-ai-cli.spec.ts`                    |
| Git                                       | git-CLI ohne Shell, feste Befehle, Pfade über FsVault geprüft und als `:(literal)`-Pfade übergeben, Revisionen geprüft, `GIT_TERMINAL_PROMPT=0`                                                                                                                                                                                              | `electron/git.test.ts`, `e2e/electron-git.spec.ts`                         |
| MCP-Server                                | arbeitet nur im übergebenen Ordner (FsVault mit `realpath`-Prüfung), `--read-only` bietet nur lesende Werkzeuge an, Hinweise `destructiveHint`                                                                                                                                                                                               | `mcp/server.test.ts`, `e2e/electron.spec.ts`                               |
| Moodle                                    | nur im Hauptprozess; https (http nur localhost); keine Umleitung auf fremde Server; Passwort wird nur an `login/token.php` geschickt und nie gespeichert; Token bzw. Kalender-Link verschlüsselt per `safeStorage` im Profil (nie im Vault/Git); Antworten werden als nicht vertrauenswürdig normalisiert (HTML entfernt, nur http(s)-Links) | `electron/moodle.test.ts`, `moodle.test.ts`, `e2e/electron-moodle.spec.ts` |
| eCampus (HISinOne)                        | Anmeldung im eigenen Fenster mit getrennter Sitzung (`persist:ecampus`, Sandbox, keine Brücke, Passkeys aus); Notiva liest nur Tabellen/Links der Seiten (Skript im Hauptprozess, Ergebnisse als nicht vertrauenswürdig geparst); kein Passwort gespeichert, nur Adressen und Ergebnisse im App-Profil; Sitzungs-Cookies nur dieser Sitzung werden 14 Tage behalten (wie „angemeldet bleiben“), damit die Prüfung im Hintergrund still über die Hochschul-Anmeldung erneuert werden kann – ein Anmeldeformular heißt „neu anmelden“, nie wird etwas eingetippt; nur eine Notiva pro Profil (Single-Instance-Lock, Entwicklungsversion neben der installierten nutzt ein eigenes Profil)                                       | `ecampus.test.ts`, `e2e/electron-ecampus.spec.ts`                          |
| Vorlesungsmodus (Mikrofon)                | Mikrofon nur für Notivas eigenes Fenster und nur Audio (Berechtigungsprüfung im Hauptprozess), macOS fragt einmal nach; lokales Whisper lauscht nur auf 127.0.0.1, Modelle per SHA-256 geprüft, Server endet mit Notiva (auch bei Absturz); Tests nutzen eine Audiodatei statt des echten Mikrofons                                          | `electron/whisper.test.ts`, `e2e/electron-lecture.spec.ts`                 |
| Dateien lesen (`read_file`)               | nur Dateien aus der Vault-Liste (kein Pfad von außen), nur Text-Formate und PDF (max. 25 MB), PDF-Text mit pdf.js ohne Skripte/XFA/Schriften, Inhalte sind Daten                                                                                                                                                                             | `ai-tools.test.ts`, `pdfText.test.ts`                                      |

Wer gar keine Verbindungen möchte, entfernt die Hosts aus `connect-src` in `index.html` – Ollama/LM Studio auf
`localhost` bleiben dann trotzdem nutzbar, wenn nur `http://localhost:*` stehen bleibt.

Bilder von `https:` sind erlaubt (Markdown-Bilder aus dem Netz); wer das nicht möchte, entfernt `https:` aus `img-src`
in `index.html` und `electron/main.ts`.

Sicherheitsprobleme bitte nicht öffentlich melden, sondern direkt an den Maintainer (GitHub: flexi03).
